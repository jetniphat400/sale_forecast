WHY THIS LOG IS SUPERSEDED
--------------------------
WRONG SCOPE ONLY -- date key and model are UNCHANGED and still correct. Phase C step 2 expanded
this project's forecasting scope from the 128-item PEM101-sheet Fuse+Surge Category pilot to the
full 335-item, 5-division scope (PEM101, PEM102, PEM103, PEM107, CI101 -- PEM104 contributes zero
forecast-status items, all 12 of its codes excluded for a data-volume reason, see
output/summary/phaseC_step1revised_item_status_445.csv). 222 of the 335 current-scope items never
appear in this log at all -- it covers only the PEM101 sheet's Fuse+Surge Category codes.

The date key (forecast_date, "adopted_series_key": "forecastDate") and the forecasting method
(Top-down allocation of a Type-level Combination forecast, "adopted_item_level_approach":
"Top-down") are IDENTICAL between this archived log and its replacement -- neither changed.
This is a pure scope supersession, not a method change, unlike the 58-item log's three-way
supersession (see SUPERSEDED_forward_test_log_58items_createDate_README.txt in this same folder).

Because the scope changed, this log could never be meaningfully extended to the current 335-item
scope by scoring alone -- it simply never generated forecasts for 222 of the current items. It is
kept here, unmodified, for historical record only (archive, never delete -- nothing here has been
altered from the live files as they stood on 2026-09-07).

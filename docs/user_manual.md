# คู่มือการใช้ Dashboard

## เริ่มตรงนี้

Dashboard นี้มี 5 ส่วน

| ส่วน | ใช้ตอบคำถาม | ข้อมูลใหม่ไหม |
|---|---|---|
| แผงสต็อคจริง | ตอนนี้มีของอยู่เท่าไหร่ อยู่คลังไหน ติดจองเท่าไหร่ | อัปเดตทุกเดือน |
| หน้ายอดขาย (Sales) | model ทายยอดขายแม่นแค่ไหน ใช้ได้แค่ไหน | อัปเดตทุกเดือน |
| หน้า Min-Max | ถ้าตั้งนโยบาย stock แบบนี้ ต้องถือของเท่าไหร่ | เครื่องมือจำลอง |
| แท็บ Trend Omni | สินค้าแต่ละตัวขายแบบไหน ขึ้นลงยังไง | ข้อมูลถึง 25 ส.ค. 2569 |
| แท็บ S&OP Plan | แผนตัวอย่างสำหรับนำเสนอ | ไม่อัปเดต ตัวเลขเป็นตัวอย่าง |

ดูว่าข้อมูลใหม่แค่ไหน — ทุกหน้ามี 2 เวลาใต้หัวข้อ
- ข้อมูลดึงเมื่อ = วันที่ดึงข้อมูลจากระบบ ดูอันนี้
- หน้าสร้างเมื่อ = วันที่สร้างหน้า

ถ้าข้อมูลเก่ากว่า 7 วันจะมีป้ายเตือนสีเหลือง

## ศัพท์ที่ต้องรู้

### ยอดขาย
- Actual — ยอดที่ส่งของแล้ว
- MPS — PO ที่รับแล้วแต่ยังไม่ส่ง นับเป็นยอดขายด้วย เพราะลูกค้าสั่งแล้วจริง
- วันส่งตามสัญญา — ยอดขายทุกกราฟนับตามเดือนที่ต้องส่งของ ไม่ใช่เดือนที่รับ PO

### ความแม่นของการทาย
- MAE — ทายพลาดเฉลี่ยกี่ชิ้นต่อเดือน ทายเกินหรือขาดนับเท่ากัน สมมติ MAE = 120 คือแต่ละเดือนทายห่างจากยอดจริงประมาณ 120 ชิ้น ใช้เทียบวิธีทายในสินค้าหรือฝ่ายเดียวกัน อย่าเทียบข้ามฝ่าย ฝ่ายที่ขายเยอะ MAE สูงกว่าเสมอ
- RMSE — คล้าย MAE แต่ลงโทษการพลาดก้อนใหญ่หนักกว่า ถ้า RMSE สูงกว่า MAE มาก แปลว่ามีบางเดือนพลาดหนัก
- Bias — ทายเกินหรือขาดเป็นนิสัยไหม ติดลบ = ทายต่ำกว่ายอดจริง ถ้าใช้วางแผน stock ของจะขาด บวก = ทายสูงไป
- MASE — ดีกว่าวิธีเดาง่ายๆ ไหม วิธีเดาง่ายคือใช้ยอดเดือนก่อนเป็นตัวทาย ต่ำกว่า 1 = ดีกว่าเดาง่าย สูงกว่า 1 = แย่กว่า ถ้าขึ้น MASE_undefined คือสินค้าตัวนั้นยอดเท่ากันทุกเดือนหรือเป็นศูนย์ คิดค่านี้ไม่ได้
- Rolling origin — วิธีทดสอบ ตัดข้อมูลที่จุดหนึ่งในอดีต ให้ model ทาย 6 เดือนถัดไป แล้วเทียบกับยอดจริง ทำซ้ำ 7 จุด ผลที่รายงานคือค่าเฉลี่ย 7 รอบ

### วิธีทาย
- Top-down — วิธีที่ใช้จริง ทายยอดรวมทั้งกลุ่มประเภทสินค้าก่อน แล้วแบ่งให้แต่ละรหัสตามสัดส่วนที่เคยขาย
- Combination — เอาผลจาก 6 วิธีทายพื้นฐานมาเฉลี่ยกัน

### การส่งของ
- ส่งไม่ช้า (not_late) — ส่งทันวันนัดหรือก่อน ใช้ตัวนี้เมื่อพูดถึงการส่งทัน
- ส่งตรงวันพอดี (on_time_exact) — นับเฉพาะส่งวันนัดเป๊ะ ต่ำกว่าเสมอเพราะไม่นับที่ส่งก่อน ห้ามใช้รายงานเป็นอัตราส่งทัน

### รูปแบบการขาย (ใช้ในแท็บ Trend)
- ADI — ขายห่างกันเฉลี่ยกี่เดือนต่อครั้ง ADI = 1 คือขายทุกเดือน ADI = 4 คือ 4 เดือนขายครั้ง
- CV² — ขนาดออเดอร์แกว่งแค่ไหน ยิ่งสูงยิ่งไม่สม่ำเสมอ
- Smooth — ขายบ่อย ขนาดสม่ำเสมอ ทายง่ายสุด
- Erratic — ขายบ่อย ขนาดแกว่ง
- Intermittent — ขายห่าง ขนาดสม่ำเสมอ
- Lumpy — ขายห่าง ขนาดแกว่ง ทายยากสุด

### Stock
- Sellable — stock ในคลังที่ถือว่าหยิบขายได้ รายชื่อคลังเป็นสมมติฐาน ยังไม่ได้ยืนยันจากฝ่ายคลัง
- Staging — stock ในคลัง QA / FMTS / FMTO ยังไม่พร้อมขาย
- Reserved — จำนวนที่มี PO จองไว้แล้วแต่ยังไม่ส่ง
- Available — stock ลบ Reserved ตอนนี้ยังรวม stock ในคลังที่ขายไม่ได้ ดูข้อควรระวังของแผงสต็อค
- Min — ถ้า stock ลดถึงระดับนี้ ต้องสั่งเติม
- Max — สั่งเติมให้ถึงระดับนี้
- Months of cover — stock ที่มีพอขายได้กี่เดือน
- Placeholder — สินค้าที่ไม่มีประวัติขาย ตัวเลขเป็นค่าประมาณคร่าวๆ ห้ามใช้สั่งของ

## แผงสต็อคจริง

เปิดยังไง — แท็บ S&OP Plan ส่วนที่ 1 คลิกแถว "Inventory — แผนสต็อค" หรือกด Enter กลับด้วยปุ่ม "กลับไปหน้า S&OP Plan"

ใช้ตอบ — ตอนนี้สินค้าแต่ละตัวมีของเท่าไหร่ อยู่คลังไหน ติดจองเท่าไหร่

### ตัวเลขสรุปด้านบน
จำนวนรหัสทั้งหมด / มีสต็อค / สต็อคเป็นศูนย์ / ไม่มีข้อมูลในระบบ ซึ่งหมายถึงรหัสนี้ไม่มีบันทึกในระบบคลังเลย ต่างจากสต็อคเป็นศูนย์

### ตาราง Sellable / Staging / Elsewhere ต่อฝ่าย
▸ stock ของแต่ละฝ่ายแยกเป็น 3 กอง คลังที่ขายได้ / คลังตรวจ QA ที่ยังไม่พร้อม / คลังอื่น หน่วยเป็นชิ้น
▸ คอลัมน์ Sellable warehouse codes บอกว่าคลังไหนถูกนับเป็นคลังขายได้ รายชื่อนี้เป็นสมมติฐาน ยังไม่ได้ยืนยันจากฝ่ายคลัง
▸ CI101 / PEM102 / PEM104 ขึ้น not assessed เพราะยังไม่ได้กำหนดคลังขายได้ ไม่ใช่ศูนย์

### ตารางรายสินค้า
- Inventory (qty) = stock ทุกคลังรวมกัน คลิกตัวเลขเพื่อดูแยกรายคลัง
- Sellable / Staging / Elsewhere = แยกตามตารางข้างบน
- Reserved = คลิกตัวเลขเพื่อดูรายการ PO ที่จอง รายการที่ขึ้น "อาจซ้ำ — โปรดตรวจสอบ" คือระบบสงสัยว่าซ้ำ ให้คนตรวจ ไม่ได้แปลว่าซ้ำแน่
- Available = Inventory ลบ Reserved
- Lead time (วัน) = ช่องให้กรอกเอง
- คลิกหัวคอลัมน์เพื่อเรียง

อ่านยังไง — สมมติสินค้าตัวหนึ่ง Inventory 100, Sellable 80, Staging 20, Reserved 50 ของที่หยิบส่งได้จริงคือ 80 − 50 = 30 ไม่ใช่ Available ที่ขึ้น 50

### ระวัง
- Available ยังนับ stock ในคลัง QA ด้วย จึงดูสูงกว่าที่หยิบได้จริง ให้คิดจาก Sellable ลบ Reserved แทน
- Lead time ที่กรอกเก็บไว้ใน browser ของคุณเท่านั้น คนอื่นไม่เห็น ล้าง browser แล้วหาย
- ช่องค้นหาและตัวกรองฝ่าย หมวด แค่ซ่อนแถว ไม่ได้คำนวณยอดรวมใหม่
- Stock กับ Reserved ดึงคนละเวลา ดูวันที่ของแต่ละอันด้านบน

## หน้ายอดขาย (Sales)

ใช้ตอบ — model ทายยอดขายแม่นแค่ไหน และทำไมเลือกวิธีนี้

### กราฟระยะเวลาแจ้งล่วงหน้า
▸ ลูกค้าสั่งของล่วงหน้านานแค่ไหนก่อนวันที่ต้องส่ง
▸ แกน X = ระยะแจ้งล่วงหน้าขั้นต่ำ (≥30 วัน, ≥60 วัน … ≥180 วัน) · แกน Y = % ของออเดอร์ทั้งหมด
▸ สมมติแท่ง ≥30 วันสูง 6% หมายถึงออเดอร์ 100 ใบ มีแค่ 6 ใบที่แจ้งล่วงหน้าเกิน 30 วัน

ตัวเลขนี้คือเหตุผลหลักของโปรเจกต์ ลูกค้าส่วนใหญ่แจ้งล่วงหน้าไม่กี่วัน แต่สั่งวัตถุดิบใช้ 45-60 วัน ผลิตตามออเดอร์ไม่ทัน ต้องมีของรอไว้ก่อน

### กราฟสัดส่วนส่งมอบ
▸ ส่งของให้ลูกค้าทันวันนัดกี่ % ต่อปี
▸ แกน X = ปี · แกน Y = % (0-100)
▸ 2 เส้น ส่งไม่ช้า (ทันหรือก่อนวันนัด) กับ ส่งตรงวันพอดี ใช้เส้นส่งไม่ช้าถ้าจะตอบว่าลูกค้าได้ของทันไหม
▸ เส้นส่งตรงวันพอดีต่ำกว่าเสมอเพราะไม่นับที่ส่งก่อน อย่าเอาไปรายงานเป็นอัตราส่งทัน

สองเส้นนับต่างกันด้วย ส่งไม่ช้านับเป็นชิ้น ส่งตรงวันนับเป็นรายการ จึงเทียบกันตรงๆ ไม่ได้

### กราฟ MAE ของ 6 วิธีพื้นฐาน เทียบ Combination และ Top-down
▸ แต่ละวิธีทายสินค้าหลัก 3 ตัวพลาดแค่ไหน
▸ แกน X = รหัสสินค้า 3 ตัว · แกน Y = MAE (ชิ้นต่อเดือน) แท่งต่ำ = ทายแม่นกว่า
▸ แต่ละสีคือหนึ่งวิธี คลิกชื่อใน legend เพื่อซ่อนหรือแสดง

ไม่มีวิธีเดียวที่ชนะทุกตัว เป็นเหตุผลที่ใช้วิธีเฉลี่ยรวม

### ส่วนผลลัพธ์ — ตัวกรองมีผลต่างกัน อ่านก่อน

| ตัวกรอง | มีผลกับ |
|---|---|
| ฝ่าย | ตารางหลัก ตารางรอง กราฟ Rolling-origin |
| ประเภท | กราฟ Rolling-origin อย่างเดียว |
| Rolling origin (1-7) | กราฟ Forecast vs Actual อย่างเดียว |
| ช่องติ๊กรหัสสินค้า | กราฟ Forecast vs Actual อย่างเดียว |

### ตารางหลัก — Top-down (วิธีที่ใช้จริง)
คอลัมน์ ฝ่าย / MAE / RMSE / Bias / MASE / n_scored (จำนวนครั้งที่นำมาคำนวณ)
สมมติฝ่ายหนึ่ง MAE 10, Bias +3, MASE 0.7 หมายถึงทายพลาดเฉลี่ย 10 ชิ้นต่อเดือน ทายสูงไปเล็กน้อย และดีกว่าวิธีเดาง่าย

### ตารางรอง — Combination ระดับประเภท
เก็บไว้เทียบเท่านั้น ไม่ใช่วิธีที่ใช้

### กราฟ Rolling-origin MAE
▸ แต่ละวิธีทายแม่นสม่ำเสมอไหม ในการทดสอบแต่ละรอบ
▸ แกน X = รอบทดสอบที่ 1-7 เรียงตามเวลา · แกน Y = MAE เฉลี่ย (ชิ้นต่อเดือน)
▸ เส้นที่ต่ำและนิ่ง = ดี เส้นที่กระโดดขึ้นลง = บางช่วงทายได้ บางช่วงพลาดหนัก

### กราฟ Forecast vs Actual
▸ ทายไว้เทียบกับของจริง สินค้าที่เลือก ในรอบทดสอบที่เลือก
▸ แกน X = เดือนที่ 1-6 หลังจุดตัดข้อมูล · แกน Y = จำนวน (ชิ้น)
▸ เส้นทึบ = ยอดจริง เส้นประ = ที่ทายไว้ เส้นประอยู่ใต้เส้นทึบ = ทายต่ำไป
▸ กราฟนี้มีเฉพาะสินค้า PEM101 ตัวกรองฝ่ายไม่มีผล

### ระวัง
- Top-down ชนะวิธีอื่นแบบไม่มีนัยสำคัญทางสถิติ เลือกเพราะนิ่งและทำได้ทั้งระบบ ไม่ใช่เพราะแม่นกว่าชัดเจน
- ทุกวิธีมีแนวโน้มทายต่ำกว่าจริง
- ยอดขายนับจาก PO ที่รับแล้ว ไม่เห็นลูกค้าที่ไม่ได้สั่งเพราะรู้ว่าไม่มีของ

## หน้า Min-Max

ใช้ตอบ — ถ้าตั้งนโยบาย stock แบบนี้ ต้องถือของเท่าไหร่ มีต้นทุนเท่าไหร่

ตัวเลขทั้งหมดเป็นการจำลองภายใต้สมมติฐาน ไม่ใช่คำแนะนำให้สั่งซื้อ

เลือกฝ่าย PEM101 / PEM103 / PEM107 ส่วน CI101 PEM102 PEM104 ปิดไว้ ชี้เมาส์ดูเหตุผล

| ฝ่าย | ความน่าเชื่อถือ |
|---|---|
| PEM101 | calibrate กับข้อมูลจริงแล้วบางส่วน ใช้ส่วน Trade-off Curve |
| PEM103 | ไม่ควรใช้วางแผน ฝ่ายนี้ผลิตตามงานประมูล ไม่ใช่ธุรกิจ stock |
| PEM107 | ยังไม่ calibrate และสินค้าส่วนใหญ่เป็นผลิตตามสั่ง มีแค่ไม่กี่ตัวที่เข้าเกณฑ์เก็บ stock — ดูแถบเตือนด้านบนก่อน |

### แถบเตือน PEM107
▸ การส่งทันของช่องทาง Omni ก่อนและหลัง พ.ค. 2569 พร้อมจำนวนชิ้นที่ใช้คำนวณ
▸ ตารางด้านล่างเรียงสินค้าที่ส่งช้ามากสุดก่อน มียอดรวมตามประเภทสินค้า ใช้ดูว่าช้ากระจุกที่ไม่กี่ตัวหรือทั้งฝ่าย

ระวัง หลัง พ.ค. จำนวนยังน้อย ยังไม่รู้สาเหตุแน่ชัด และยังไม่ยืนยันว่า พ.ค. แยกอะไร stock หรือสายผลิต ใช้เป็นจุดเริ่มคุยกับฝ่าย ไม่ใช่ข้อสรุป

### Trade-off Curve (PEM101 เท่านั้น) — ส่วนที่เชื่อถือได้ที่สุดของหน้า
▸ ถ้าอยากส่งทันระดับนี้ ต้องถือ stock มูลค่าเท่าไหร่
▸ แกน X = % ส่งไม่ช้า · แกน Y = มูลค่า stock (บาท)
▸ เส้นกลาง = ค่ากลาง แถบรอบเส้น = ช่วงที่เป็นไปได้ ดาว = จุดที่เราอยู่วันนี้ เพชร = เป้าที่เลือก
▸ ใช้ปุ่มเป้าสำเร็จรูป 3 ปุ่ม หรือเลื่อน slider เพื่อเลือกเป้า

ปุ่ม 1 = ส่งทันเท่าวันนี้ ด้วย stock น้อยสุด ปุ่ม 2 = stock เท่าวันนี้ ส่งทันได้สูงสุด ปุ่ม 3 = เป้า 99%
แถบกว้างมากเพราะข้อมูลบอกไม่ได้แน่ชัดว่าบริษัทสั่งเติมเมื่อ stock เหลือกี่เดือน ให้อ่านเป็นทิศทาง ไม่ใช่ตัวเลขแน่นอน
ตอนนี้ PEM101 อยู่ใกล้เส้นที่ดีที่สุดแล้ว ความต่างระหว่างดาวกับปุ่ม 1 เล็กกว่าความคลาดเคลื่อนของ model จึงพูดไม่ได้ว่าลด stock ได้

### ต้นทุนการยกระดับ (PEM101)
▸ ถ้าจะขยับการส่งทันจากวันนี้ไปถึงเป้า ต้องเพิ่ม stock กี่ %
▸ สมมติขึ้น "+20.0% (range +10.0% to +30.0%)" หมายถึงต้องถือของเพิ่มประมาณ 1 ใน 5 จากที่ถืออยู่ แย่สุด 30%

ตัวเลขนี้แม่นกว่ามูลค่าเป็นบาทในกราฟ เพราะสิ่งที่ข้อมูลบอกไม่ได้ คือบริษัทสั่งเติมเมื่อของเหลือกี่เดือน หักล้างกันเองเมื่อคิดเป็น % ใช้ตัวนี้เวลาคุยเรื่องงบ
กราฟนี้ calibrate จากชุดสินค้าก่อนแบ่งประเภทใหม่ ต่างจากชุดปัจจุบันเล็กน้อย ดูป้ายบนกราฟ

### ตัวควบคุม Tier A (ทุกฝ่าย) — เครื่องมือ "ถ้าเป็นแบบนี้ล่ะ"
ส่วนนี้ใช้สมมติฐานที่ยังไม่ได้ calibrate กับข้อมูลจริง

| ตัวควบคุม | คืออะไร | ค่าเริ่มต้น |
|---|---|---|
| Procurement lead time | สั่งวัตถุดิบถึงได้ของกี่วัน | 60 |
| Assembly time | ประกอบกี่วัน ไม่มีข้อมูลจริง เป็นค่าเดา | 3 |
| Review interval | ทบทวน stock ทุกกี่วัน | 30 |
| Cycle service level | อยากให้แต่ละรอบเติมไม่ขาดของกี่ % | 0.95 |
| Holding cost rate | ต้นทุนถือของต่อปี % ของมูลค่า | 0.20 |
| เลือกคลัง | คลังไหนนับเป็นของขายได้ | ตาม config |
| เกณฑ์ของค้าง | stock พอขายเกินกี่เดือนถือว่าค้าง | ตาม config |

### ประเภทสินค้า
▸ สินค้าแต่ละตัวถูกจัดเป็น เก็บ stock / ผลิตตามสั่ง / ยังไม่ชัด — เฉพาะ "เก็บ stock" ที่มี Min/Max
▸ ผลิตตามสั่งกับยังไม่ชัด อยู่ตารางแยกด้านล่าง

ตัดสินจากป้ายในระบบ (MTS / MTO / ETO) คู่กับพฤติกรรมจริง 3 อย่าง มีของในคลังตอนนี้ / ส่วนใหญ่ผลิตเป็น batch ไว้ก่อนลูกค้าสั่ง / ส่งได้ภายใน 14 วันหลังรับ PO
- เก็บ stock = ป้าย MTS และพฤติกรรมตรงอย่างน้อย 2 ใน 3
- ผลิตตามสั่ง = ป้าย MTO หรือ ETO และพฤติกรรมตรงไม่เกิน 1
- ยังไม่ชัด = ป้ายกับพฤติกรรมขัดกัน หรือป้ายไม่ชัด ให้ฝ่ายยืนยันก่อนตั้ง Min/Max

เกณฑ์ 14 วันและสัดส่วนต่างๆ เป็นสมมติฐาน

### เลือกคลัง
▸ ติ๊กเอาคลังเข้าหรือออกจากการนับเป็นของขายได้ stock ที่มี เดือนที่พอขาย value at risk และธงของค้างจะเปลี่ยน
▸ Min/Max ไม่เปลี่ยน เพราะคำนวณจากยอดขาย ไม่ได้ใช้ stock ปัจจุบัน

### เกณฑ์ของค้าง
▸ สินค้าที่ stock พอขายเกินจำนวนเดือนที่ตั้ง จะขึ้นธงของค้าง
▸ สินค้าที่มีของแต่ไม่มียอดทายเลย แยกเป็นรายการ "สินค้าที่มีของแต่ไม่มียอดทาย"

กล่องสรุป — มูลค่า stock (Σ Min × ต้นทุนต่อชิ้น) / ต้นทุนถือของต่อปี / จำนวนสินค้าที่มี Min-Max

### กราฟ Stock value vs Cycle Service Level
▸ ยิ่งอยากไม่ขาดของ ต้องถือของเพิ่มแค่ไหน
▸ แกน X = cycle service level (0.80-0.99) · แกน Y = มูลค่า stock (บาท)
▸ เส้นชันขึ้นช่วงท้าย = ช่วงที่เพิ่ม service อีกนิดต้องจ่ายแพงมาก

### กราฟ Min เทียบกับค่าปัจจุบัน
▸ Min ที่จำลองได้ เทียบกับ Min ที่ตั้งอยู่ในระบบตอนนี้
▸ แกน X = รหัสสินค้า · แกน Y = จำนวน (ชิ้น)
▸ ค่าปัจจุบันในระบบไม่มีใครใช้จริงและตั้งไว้ไม่สม่ำเสมอ ใช้ดูว่าต่างกันแค่ไหนเท่านั้น

ตารางรายสินค้า — Min / Max / Current Min / Months of cover (∞ = ไม่มียอดทาย) / Value at risk = ถ้า Min ในระบบสูงกว่าที่จำลอง ส่วนเกินคิดเป็นเงินเท่าไหร่

### ระวัง
- ตัวเลขบนหน้านี้ต่างจากที่ระบบคำนวณเต็มประมาณ 3% เพราะหน้านี้ประมาณจากข้อมูลรายเดือน
- Placeholder และ Excluded อยู่ตารางแยก ไม่มี Min-Max

## แท็บ Trend Omni

ข้อมูลถึง 25 ส.ค. 2569 ไม่อัปเดต ใช้ฐาน 448 รหัส ซึ่งรวม sheet ที่ซ่อนใน pricelist ต่างจากหน้าอื่นที่ใช้ 445 รหัส เทียบตัวเลขข้ามหน้าตรงๆ ไม่ได้

ใช้ตอบ — สินค้าแต่ละตัวขายแบบไหน ยอดขึ้นลงยังไง

ตัวกรองด้านบน ฝ่าย / หมวด / ประเภท / กลุ่มรูปแบบการขาย / ค้นหา มีผลกับทุกกราฟและตาราง ยกเว้น เส้นเฉลี่ยมีผลแค่กราฟ ① และกราฟในหน้ารายสินค้า และปุ่มหน่วย บาท-จำนวน มีผลกับกราฟ ① ④ และตัวเลขสรุป

### กราฟ ① Trend รวมรายเดือน
▸ ยอดขายรวมแต่ละเดือนของสินค้าที่เลือก
▸ แกน X = เดือน (ม.ค. 2567 - ส.ค. 2569) · แกน Y = บาท หรือ ชิ้น ตามปุ่มหน่วย
▸ แท่งเข้ม = ส่งแล้ว แท่งอ่อนซ้อนบน = PO ที่รับแล้วยังไม่ส่ง เส้นประ = ค่าเฉลี่ยเคลื่อนที่
▸ แท่งสุดท้ายจางเพราะเดือนยังไม่จบ คลิกแท่งเพื่อดูรายวัน

### กราฟ ② แผนที่รูปแบบการขาย (ADI × CV²)
▸ สินค้าแต่ละตัวขายบ่อยแค่ไหน ขนาดออเดอร์แกว่งแค่ไหน
▸ แกน X = ADI (ขายห่างกันกี่เดือน) · แกน Y = CV² (ออเดอร์แกว่งแค่ไหน)
▸ เส้นแบ่ง 4 ช่อง ซ้ายล่าง Smooth ซ้ายบน Erratic ขวาล่าง Intermittent ขวาบน Lumpy
▸ วงใหญ่ = ยอดขายสูง ขนาดวงคิดจากบาทเสมอ ไม่ตามปุ่มหน่วย ค่าเกินขอบถูกตรึงไว้ที่ขอบ คลิกวงเพื่อดูรายสินค้า

สินค้ามุมขวาบน (Lumpy) ทายยากสุด ต้องเผื่อ stock มากสุด

### กราฟ ④ ยอดรวมแยกฝ่าย
▸ ความยาวแท่ง = ยอดรวม (บาทหรือชิ้น) · แต่ละแถว = ฝ่าย
▸ คลิกแท่งเพื่อกรองเฉพาะฝ่ายนั้น คลิกซ้ำเพื่อยกเลิก

### ตาราง ③ รายสินค้า
เรียงได้เฉพาะ 4 คอลัมน์ รหัส / ADI / Qty รวม / ยอดขาย แสดงสูงสุด 400 แถว คลิกแถวเพื่อดูรายสินค้า
คอลัมน์ Remark (Match / Check spec ฯลฯ) ไม่มีบันทึกว่าคำนวณยังไง ใช้อ้างอิงเท่านั้น

## แท็บ S&OP Plan

ทั้งแท็บเป็นตัวอย่างสำหรับนำเสนอ พิมพ์ไว้ครั้งเดียว ไม่อัปเดต ห้ามใช้ตัวเลขในแท็บนี้ตัดสินใจ ยกเว้นแผงสต็อคจริงที่เปิดจากแถว Inventory

- ตัวเลขสรุปด้านบน — ค่าคงที่ ไม่ได้คำนวณจากระบบ
- ส่วนที่ 1 ตารางรายเดือน — สีฟ้า = History สีส้ม = Plan (ตัวอย่าง) คอลัมน์ Odoo Module เป็นข้อเสนอ ยังไม่ได้เชื่อมจริง
- ส่วนที่ 2 กราฟ Actual vs Forecast — แกน X = เดือน ม.ค.-ธ.ค. แกน Y = ยอดขาย (ล้านบาท) เส้นทึบ = ยอดจริง เส้นประ = ตัวอย่างการพยากรณ์ ชี้เมาส์ไม่มีค่าขึ้น
- ส่วนที่ 4 ตารางรายสินค้า — ป้าย "ข้อมูลจริง" / "ตัวอย่าง" บอกแต่ละแถว Min/Max ทุกแถวเป็น "คำนวณตัวอย่าง" ตัวกรองแค่ซ่อนแถว
- ส่วนที่ 5 — ปัจจัยสภาพอากาศและการจัดซื้อการไฟฟ้า ยังไม่ได้นำมาใช้จริง

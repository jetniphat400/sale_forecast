# คู่มือการใช้ Dashboard

## เริ่มตรงนี้

Dashboard นี้แบ่งเป็นหลายส่วน ตามตารางนี้ แต่ละส่วนมีหัวข้อของตัวเองในคู่มือ

| ส่วน | ใช้ตอบคำถาม | ข้อมูลใหม่ไหม |
|---|---|---|
| แผง stock จริง | ตอนนี้มีของอยู่เท่าไหร่ อยู่คลังไหน ติดจองเท่าไหร่ | อัปเดตทุกวันทำการ (จันทร์ถึงศุกร์) |
| หน้ายอดขาย (Sales) | model Forecast ยอดขายแม่นแค่ไหน ใช้ได้แค่ไหน | อัปเดตทุกเดือน |
| หน้า Min-Max | ถ้าตั้งนโยบาย stock แบบนี้ ต้องถือของเท่าไหร่ | เครื่องมือจำลอง |
| แท็บ Trend Price List Omni ปี 67–69 | สินค้าแต่ละตัวขายแบบไหน ขึ้นลงยังไง | อัปเดตทุกเดือน ข้อมูลขายใน DB (cube_Sale_APD) ถึง {trend_data_through} |
| แท็บ สรุปผู้บริหาร | ปีนี้ขายไปแล้วเท่าไหร่ คาดว่าทั้งปีเท่าไหร่ Forecast เชื่อได้แค่ไหน (Forecast = ยอดขายที่ระบบคาดการณ์) แยกตามฝ่าย | อัปเดตทุกเดือน |
| Production Plan (แผนผลิต) | แต่ละเดือนต้องผลิตอะไรเท่าไหร่ | อัปเดตทุกเดือน ใช้ stock จากการดึงรายวันล่าสุดตอนสร้างแผน |
| แผนวัตถุดิบ | วัตถุดิบตัวไหนต้องสั่งเมื่อไหร่ให้ทันแผนการผลิต (ร่าง ยังใช้สั่งซื้อจริงไม่ได้) | อัปเดตทุกเดือน |
| แท็บ S&OP Plan (เดิม) | แผนตัวอย่างสำหรับนำเสนอ | ไม่อัปเดต ตัวเลขเป็นตัวอย่าง |

ดูว่าข้อมูลใหม่แค่ไหน — แต่ละหน้าแสดงเวลาไม่เหมือนกัน
- หน้ายอดขาย (Sales) และหน้า Min-Max = แสดงทั้ง ข้อมูลดึงเมื่อ (วันที่ดึงข้อมูลจาก DB (cube_Sale_APD) สำหรับยอดขาย, DB (Cube_CES) สำหรับการส่งของ และ DB (Cube_Inventory_Exact) สำหรับ stock ของหน้า Min-Max) และ หน้าสร้างเมื่อ (วันที่สร้างหน้า)
- แผง stock จริง = แสดง ดึงข้อมูลเมื่อ ซึ่งเป็นเวลาที่สร้างไฟล์ข้อมูล stock ส่วน stock กับ Reserved ดึงคนละเวลา และมีป้าย "เก่า" แยกกัน
- Production Plan และแผนวัตถุดิบ = แสดงเวลาที่ดึงข้อมูลจาก DB (stock) และรอบ Forecast ที่ใช้ ไม่มีเวลาที่สร้างหน้า
- แท็บ Trend Price List Omni ปี 67–69 และสรุปผู้บริหาร = แสดงว่าข้อมูลขายถึงวันไหนหรือเดือนไหน ไม่มีเวลาดึงและเวลาสร้างหน้า

ป้าย "เก่า" ดูตามรอบดึงของแต่ละข้อมูล ข้อมูลที่ดึงรายเดือนเก่าเมื่อดึงก่อนรอบรายเดือนล่าสุด (ตอนนี้ {stale_monthly}) ข้อมูลที่ดึงรายวันเก่าเมื่อดึงก่อน {stale_daily} วันทำการก่อนหน้า

## ศัพท์ที่ต้องรู้

### ยอดขาย
- Actual — ยอดที่ส่งของแล้ว
- MPS (open PO) — PO ที่รับแล้วแต่ยังไม่ส่ง ยังไม่ใช่ยอดที่ส่งมอบแล้ว แต่โมเดล Forecast และกราฟนับรวมเป็นความต้องการ (Actual + MPS) เพราะลูกค้าสั่งแล้วจริง
- วันส่งตามสัญญา — ยอดขายทุกกราฟนับตามเดือนที่ต้องส่งของ ไม่ใช่เดือนที่รับ PO

### ความแม่นของ Forecast
- MAE — Forecast คลาดจากยอดจริงเฉลี่ยกี่ชิ้นต่อเดือน Forecast สูงหรือต่ำกว่าจริงนับเท่ากัน ตัวอย่าง: MAE = 120 คือแต่ละเดือน Forecast ห่างจากยอดจริงประมาณ 120 ชิ้น ใช้เทียบวิธีคำนวณ Forecast ในสินค้าหรือฝ่ายเดียวกัน อย่าเทียบข้ามฝ่าย ฝ่ายที่ขายเยอะ MAE มักสูงกว่า
- RMSE — คล้าย MAE แต่ลงโทษการพลาดก้อนใหญ่หนักกว่า ถ้า RMSE สูงกว่า MAE มาก แปลว่ามีบางเดือนพลาดหนัก
- Bias — Forecast สูงหรือต่ำกว่าจริงเป็นนิสัยไหม ติดลบ = Forecast ต่ำกว่ายอดจริง ถ้าใช้วางแผน stock ของจะขาด บวก = Forecast สูงไป
- MASE (เทียบกับ Naive; ต่ำกว่า 1 = ดีกว่า Naive) — สูงกว่า 1 = แย่กว่า Naive (ใช้ยอดเดือนล่าสุดเป็น Forecast ทุกเดือน) ถ้าขึ้น MASE_undefined คือสินค้าตัวนั้นยอดเท่ากันทุกเดือนหรือเป็นศูนย์ คิดค่านี้ไม่ได้
- Rolling origin — วิธีทดสอบ ตัดข้อมูลที่จุดหนึ่งในอดีต ให้ model Forecast {holdout_months} เดือนถัดไป แล้วเทียบกับยอดจริง ทำซ้ำ {n_rounds} จุด ผลที่รายงานคือค่าเฉลี่ย {n_rounds} รอบ
- Relative MAE — MAE ของเรา ÷ MAE ของ Naive (ใช้ยอดเดือนล่าสุดเป็น Forecast ทุกเดือน) ในเดือนทดสอบเดียวกัน ต่ำกว่า 1 = พลาดน้อยกว่า Naive ในการทดสอบนั้น เท่ากับ 1 = พลาดเท่า Naive สูงกว่า 1 = พลาดมากกว่า Naive ตัวอย่างการอ่าน: MAE ของเรา 8 ชิ้น MAE ของ Naive 10 ชิ้น Relative MAE = 0.8
- Horizon 3 — Forecast ล่วงหน้า 3 เดือน ใช้ดูความแม่นในช่วงที่ต้องสั่งวัตถุดิบล่วงหน้า ตารางเทียบกับร่างเกณฑ์แสดง Relative MAE ของ Horizon 3 แยกอีกคอลัมน์ เพื่อดูแยกจากผลรวมทั้ง {holdout_months} เดือน
- Tracking Signal (ตัวชี้ว่า Forecast เอียงไปทางเดียวต่อเนื่อง) — ใกล้ 0 = ปกติ ติดลบ = Forecast ต่ำกว่าจริงต่อเนื่อง บวก = Forecast สูงกว่าจริงต่อเนื่อง เกินเส้นเตือน (± ค่าที่เขียนไว้ในแท็บ "สมมติฐานที่ใช้อยู่") = เตือน

### วิธีคำนวณ Forecast
- Top-down — วิธีที่ใช้จริง Forecast ยอดรวมทั้งกลุ่มประเภทสินค้าก่อน แล้วแบ่งให้แต่ละรหัสตามสัดส่วนที่เคยขาย
- Combination — เอาผลจาก 6 วิธีคำนวณ Forecast พื้นฐานมาเฉลี่ยกัน

### เกณฑ์ร่าง (Draft criteria)
- เกณฑ์ Relative MAE และ Tracking Signal ในตาราง "เทียบกับร่างเกณฑ์" ของหน้ายอดขายเป็นร่าง ค่าที่ใช้อยู่และวันที่ยืนยันดูในแท็บ "สมมติฐานที่ใช้อยู่" ผู้บริหารเป็นผู้ยืนยัน
- "ถึงเกณฑ์ผ่าน (ร่าง)" แปลว่า Relative MAE ต่ำกว่าเส้นที่เสนอไว้ ยังไม่ได้พิสูจน์ว่าดีกว่า Naive จริง เพราะทดสอบย้อนหลังมีไม่กี่รอบ ให้ดูคู่กับหัวข้อ "ใช้วิธี Top-down ดีกว่าวิธีอื่นไหม" ซึ่งบอกว่าความต่างจาก Naive เกิดจริงหรือไม่ (statistically significant)

### Shadow forecast (Forecast ทดลอง)
- คือ forecast ที่คำนวณด้วยอีกวิธีหนึ่งคู่กับ forecast จริง เพื่อดูว่าวิธีนั้นดีกว่าไหมก่อนตัดสินใจเปลี่ยน ตอนนี้ใช้กับกลุ่ม Surge Arrester ด้วยวิธี Holt (วิธีคำนวณ Forecast ที่ดูแนวโน้มยอดขายที่ขึ้นหรือลง)
- ไม่เข้าแผนใดเลย Min-Max แผนผลิต แผนวัตถุดิบใช้ forecast จริงเท่านั้น
- เทียบกับยอดจริงได้ต่อเมื่อเดือนนั้นผ่านช่วงรอ (leakage guard) แล้ว เพื่อให้รายการที่คีย์ช้าเข้า DB (cube_Sale_APD) ครบก่อน ระบบไม่มีทางลัดให้ข้ามช่วงนี้
- ตัดสินด้วยกติกาที่เขียนไว้ล่วงหน้า (pre-registered rule) ก่อนเห็นผล ผลที่ออกเป็นคำแนะนำ การเปลี่ยนวิธีจริงต้องให้ผู้บริหารอนุมัติ สถานะล่าสุดอยู่ใต้ตารางกลุ่มนำร่องในหน้ายอดขาย

### ราคาที่ใช้แปลงเป็นบาท (Realized average price)
- ตัวเลขบาทในหน้ายอดขาย = จำนวนชิ้น × ราคาขายเฉลี่ยจริงของรหัสนั้น (realized average price = ยอดขายเป็นบาท ÷ จำนวนชิ้นที่ขายจริง ในช่วงล่าสุดของข้อมูลที่ใช้คำนวณ Forecast) ไม่ใช่ราคาตั้ง รหัสที่ไม่เคยขายใช้ราคาตั้งใน Price List แทน
- ยอดจริงเป็นบาทจึงเป็นค่าประมาณจากจำนวนชิ้น ไม่ใช่รายได้ตามบัญชี Forecast และยอดจริงใช้ราคาเดียวกัน เพื่อดูว่า Forecast จำนวนคลาดคิดเป็นเงินเท่าไหร่

### ฐานวันที่ของข้อมูล (Date basis)
- ฐานวันส่งตามสัญญา ใช้กับโมเดล Forecast หน้ายอดขาย และหน้าสรุปผู้บริหาร ยอดขายนับตามเดือนที่ต้องส่งของ
- ฐานวันที่รับ PO ใช้กับแท็บ Trend Price List Omni ปี 67–69 จึงนับตามเดือนที่รับ PO ตัวเลขเดือนเดียวกันของสองฐานนี้ต่างกันได้ ไม่ใช่ข้อมูลผิด

### การส่งของ
- ส่งทัน (Not-late: ส่งไม่ช้ากว่าวันนัด) — คือทันวันนัดหรือก่อน ใช้ตัวนี้เมื่อพูดถึงการส่งทัน
- ส่งตรงวันพอดี (on_time_exact) — นับเฉพาะส่งวันนัดเป๊ะ ต่ำกว่าเสมอเพราะไม่นับที่ส่งก่อน ห้ามใช้รายงานเป็นอัตราส่งทัน

### รูปแบบการขาย (ใช้ในแท็บ Trend)
- ADI — ขายห่างกันเฉลี่ยกี่เดือนต่อครั้ง ตัวอย่าง: ADI = 1 คือขายทุกเดือน ADI = 4 คือ 4 เดือนขายครั้ง
- CV² — ขนาดออเดอร์แกว่งแค่ไหน ยิ่งสูงยิ่งไม่สม่ำเสมอ
- Smooth — ขายบ่อย ขนาดสม่ำเสมอ Forecast ง่ายสุด
- Erratic — ขายบ่อย ขนาดแกว่ง
- Intermittent — ขายห่าง ขนาดสม่ำเสมอ
- Lumpy — ขายห่าง ขนาดแกว่ง Forecast ยากสุด

### Stock
- Sellable — stock ในคลังที่ถือว่าหยิบขายได้ รายชื่อคลังเป็นสมมติฐาน ยังไม่ได้ยืนยันจากฝ่ายคลัง
- Staging — stock ในคลัง QA / FMTS / FMTO ยังไม่พร้อมขาย
- Reserved — จำนวนที่มี PO จองไว้แล้วแต่ยังไม่ส่ง
- Available — stock ลบ Reserved ตอนนี้ยังรวม stock ในคลังที่ขายไม่ได้ ดูข้อควรระวังของแผง stock
- Min — ถ้า stock ลดถึงระดับนี้ ต้องสั่งเติม
- Max — สั่งเติมให้ถึงระดับนี้
- Months of cover — stock ที่มีพอขายได้กี่เดือน
- Placeholder — สินค้าที่ไม่มีประวัติขาย ตัวเลขเป็นค่าประมาณคร่าวๆ ห้ามใช้สั่งของ

## แผง stock จริง

เปิดยังไง — แท็บ S&OP Plan (เดิม) ส่วนที่ 1 คลิกแถว "Inventory" หรือกด Enter กลับด้วยปุ่ม "กลับไปหน้า S&OP Plan"

ใช้ตอบ — ตอนนี้สินค้าแต่ละตัวมีของเท่าไหร่ อยู่คลังไหน ติดจองเท่าไหร่

### ตัวเลขสรุปด้านบน
จำนวนรหัสทั้งหมด / มี stock / stock เป็นศูนย์ / ไม่มีข้อมูลใน DB (Cube_Inventory_Exact) ซึ่งหมายถึงรหัสนี้ไม่มีบันทึกในตารางนั้นเลย ต่างจาก stock เป็นศูนย์

### ตาราง Sellable / Staging / Elsewhere ต่อฝ่าย
▸ stock ของแต่ละฝ่ายแยกเป็น 3 กอง คลังที่ขายได้ / คลังตรวจ QA ที่ยังไม่พร้อม / คลังอื่น หน่วยเป็นชิ้น
▸ คอลัมน์ Sellable warehouse codes บอกว่าคลังไหนถูกนับเป็นคลังขายได้ รายชื่อนี้เป็นสมมติฐาน ยังไม่ได้ยืนยันจากฝ่ายคลัง
▸ CI101 / PEM102 / PEM104 ขึ้น not assessed เพราะยังไม่ได้กำหนดคลังขายได้ ไม่ใช่ศูนย์

### ตารางรายสินค้า
- Inventory (qty) = stock ทุกคลังรวมกัน คลิกตัวเลขเพื่อดูแยกรายคลัง
- Sellable / Staging / Elsewhere = แยกตามตารางข้างบน
- Reserved = คลิกตัวเลขเพื่อดูรายการ PO ที่จอง รายการที่ขึ้น "อาจซ้ำ — โปรดตรวจสอบ" คือระบบสงสัยว่าซ้ำ ให้คนตรวจ ไม่ได้แปลว่าซ้ำแน่
- Available = Inventory ลบ Reserved Reserved และ Available นับออเดอร์ของทุกช่องทาง (stock ใช้ร่วมกันทุกช่องทาง) ส่วนแผนการผลิตของ PEM103 ใช้เฉพาะออเดอร์ช่อง Omni (ไม่รวมงานประมูล)
- Lead time (วัน) = ช่องให้กรอกเอง
- คลิกหัวคอลัมน์เพื่อเรียง

อ่านยังไง — ตัวอย่าง: สินค้าตัวหนึ่ง Inventory 100, Sellable 80, Staging 20, Reserved 50 ของที่หยิบส่งได้จริงคือ 80 − 50 = 30 ไม่ใช่ Available ที่ขึ้น 50

### ระวัง
- Available ยังนับ stock ในคลัง QA ด้วย จึงดูสูงกว่าที่หยิบได้จริง ให้คิดจาก Sellable ลบ Reserved แทน
- Lead time ที่กรอกเก็บไว้ใน browser ของคุณเท่านั้น คนอื่นไม่เห็น ล้าง browser แล้วหาย
- ช่องค้นหาและตัวกรองฝ่าย หมวด แค่ซ่อนแถว ไม่ได้คำนวณยอดรวมใหม่
- Stock กับ Reserved ดึงคนละเวลา ดูวันที่ของแต่ละอันด้านบน

## หน้ายอดขาย (Sales)

ใช้ตอบ — model Forecast ยอดขายแม่นแค่ไหน และทำไมเลือกวิธีนี้

▸ ลูกค้า PEM101 (128 รหัส) สั่งของล่วงหน้านานแค่ไหนก่อนวันที่ต้องส่ง
▸ แกน X = ระยะแจ้งล่วงหน้าขั้นต่ำ (≥{notice_bucket_first} วัน, ≥{notice_bucket_second} วัน … ≥{notice_bucket_last} วัน) · แกน Y = % ของออเดอร์ทั้งหมด
▸ ตัวอย่าง: แท่ง ≥30 วันสูง 6% หมายถึงออเดอร์ 100 ใบ มีแค่ 6 ใบที่แจ้งล่วงหน้าเกิน 30 วัน

ตัวเลขนี้คือเหตุผลหลักของโปรเจกต์ ลูกค้าส่วนใหญ่แจ้งล่วงหน้าไม่กี่วัน แต่สั่งวัตถุดิบใช้ {lead_confirmed_first}-{lead_confirmed_last} วัน ผลิตตามออเดอร์ไม่ทัน ต้องมีของรอไว้ก่อน

### กราฟสัดส่วนส่งมอบ
▸ PEM101 (128 รหัส) ส่งของให้ลูกค้าทันวันนัดกี่ % ต่อปี
▸ แกน X = ปี · แกน Y = % (0-100)
▸ 2 เส้น ส่งทัน (คือทันหรือก่อนวันนัด) กับ ส่งตรงวันพอดี ใช้เส้นส่งทันถ้าจะตอบว่าลูกค้าได้ของทันไหม
▸ เส้นส่งตรงวันพอดีต่ำกว่าเสมอเพราะไม่นับที่ส่งก่อน อย่าเอาไปรายงานเป็นอัตราส่งทัน

สองเส้นนับต่างกันด้วย ส่งทันนับเป็นชิ้น ส่งตรงวันนับเป็นรายการ จึงเทียบกันตรงๆ ไม่ได้

### กราฟ MAE ของ 6 วิธีพื้นฐาน เทียบ Combination และ Top-down
▸ Forecast ของแต่ละวิธีสำหรับสินค้าหลัก 3 ตัวคลาดแค่ไหน
▸ แกน X = รหัสสินค้า {n_focus_items} ตัว · แกน Y = MAE (ชิ้นต่อเดือน) แท่งต่ำ = Forecast แม่นกว่า
▸ แต่ละสีคือหนึ่งวิธี คลิกชื่อใน legend เพื่อซ่อนหรือแสดง

ไม่มีวิธีเดียวที่ชนะทุกตัว เป็นเหตุผลที่ใช้วิธีเฉลี่ยรวม

### ส่วนผลลัพธ์ — ตัวกรองมีผลต่างกัน อ่านก่อน

| ตัวกรอง | มีผลกับ |
|---|---|
| ฝ่าย | ตารางหลัก ตารางรอง กราฟ Rolling-origin |
| ประเภท | กราฟ Rolling-origin อย่างเดียว |
| Rolling origin (1-7) | กราฟ Forecast vs Actual อย่างเดียว |
| ช่องติ๊กรหัสสินค้า | กราฟ Forecast vs Actual อย่างเดียว |

### ตารางหลัก — Top-down (วิธีที่ใช้จริง)
คอลัมน์ ฝ่าย / MAE / RMSE / Bias / MASE / จำนวนที่ใช้คำนวณ (สินค้า × รอบทดสอบ)
ตัวอย่าง: ฝ่ายหนึ่ง MAE 10, Bias +3, MASE 0.7 หมายถึง Forecast คลาดเฉลี่ย 10 ชิ้นต่อเดือน Forecast สูงไปเล็กน้อย และดีกว่า Naive

### ตารางรอง — Combination ระดับประเภท
ผลของส่วน Combination ก่อนแบ่งลงรหัสสินค้า ใช้เทียบเท่านั้น ตัวเลขที่ใช้วางแผนคือตารางหลัก

### กราฟ Rolling-origin MAE
▸ Forecast ของแต่ละวิธีแม่นสม่ำเสมอไหม ในการทดสอบแต่ละรอบ
▸ แกน X = รอบทดสอบที่ 1-{n_rounds} เรียงตามเวลา · แกน Y = MAE เฉลี่ย (ชิ้นต่อเดือน)
▸ เส้นที่ต่ำและนิ่ง = ดี เส้นที่กระโดดขึ้นลง = บางช่วง Forecast ได้ บางช่วงพลาดหนัก

### กราฟ Forecast vs Actual
▸ Forecast เทียบกับของจริง สินค้าที่เลือก ในรอบทดสอบที่เลือก
▸ แกน X = เดือนที่ 1-{holdout_months} หลังจุดตัดข้อมูล · แกน Y = จำนวน (ชิ้น)
▸ เส้นทึบ = ยอดจริง เส้นประ = Forecast เส้นประอยู่ใต้เส้นทึบ = Forecast ต่ำไป
▸ กราฟนี้มีเฉพาะสินค้า PEM101 ตัวกรองฝ่ายไม่มีผล

### ระวัง
- ความต่างระหว่าง Top-down กับวิธีอื่นส่วนใหญ่ไม่มีนัยสำคัญทางสถิติ (ต่างจากความบังเอิญไม่ได้) เลือกเพราะนิ่งและทำได้ทั้งระบบ ไม่ใช่เพราะแม่นกว่าชัดเจน ฝ่ายไหนต่างจริงดูที่ข้อสรุปใต้ตารางผลลัพธ์
- ทุกวิธีมีแนวโน้ม Forecast ต่ำกว่าจริง
- ยอดขายนับจาก PO ที่รับแล้ว ไม่เห็นลูกค้าที่ไม่ได้สั่งเพราะรู้ว่าไม่มีของ

## หน้า Min-Max

ใช้ตอบ — ถ้าตั้งนโยบาย stock แบบนี้ ต้องถือของเท่าไหร่ มีต้นทุนเท่าไหร่

ตัวเลขทั้งหมดเป็นการจำลองภายใต้สมมติฐาน ไม่ใช่คำแนะนำให้สั่งซื้อ

ตัวควบคุมอยู่แผงซ้าย ติดจอตลอดเวลาเลื่อน · ไม่มีผลกับกราฟเป้าการส่งทัน ของ PEM101 ส่วนนั้นใช้ปุ่มเป้าและ slider ของตัวเอง

เลือกฝ่าย PEM101 / PEM103 / PEM107 ส่วน CI101 PEM102 PEM104 ปิดไว้ ชี้เมาส์ดูเหตุผล

| ฝ่าย | ความน่าเชื่อถือ |
|---|---|
| PEM101 | calibrate กับข้อมูลจริงแล้วบางส่วน ใช้ส่วน Trade-off Curve |
| PEM103 | ไม่ควรใช้วางแผน ฝ่ายนี้ไม่ใช่ธุรกิจ stock ในขอบเขตของ Dashboard นี้นับเฉพาะออเดอร์ช่อง Omni Channel ไม่รวมงานประมูล |
| PEM107 | ยังไม่ calibrate และสินค้าส่วนใหญ่เป็นผลิตตามสั่ง มีแค่ไม่กี่ตัวที่เข้าเกณฑ์เก็บ stock — ดูแถบเตือนด้านบนก่อน |

### แถบเตือน PEM107
▸ การส่งทันของช่องทาง Omni ก่อนและหลังเดือนที่แถบเตือนระบุ พร้อมจำนวนชิ้นที่ใช้คำนวณ
▸ ตารางด้านล่างเรียงสินค้าที่ส่งช้ามากสุดก่อน มียอดรวมตามประเภทสินค้า ใช้ดูว่าช้ากระจุกที่ไม่กี่ตัวหรือทั้งฝ่าย

ระวัง หลังเดือนนั้นจำนวนยังน้อย ยังไม่รู้สาเหตุแน่ชัด และยังไม่ยืนยันว่าเดือนนั้นแยกอะไร stock หรือสายผลิต ใช้เป็นจุดเริ่มคุยกับฝ่าย ไม่ใช่ข้อสรุป

### Trade-off Curve (PEM101 เท่านั้น) — ส่วนที่เชื่อถือได้ที่สุดของหน้า
▸ ถ้าอยากส่งทัน ระดับนี้ ต้องถือ stock มูลค่าเท่าไหร่
▸ แกน X = % ส่งทัน · แกน Y = มูลค่า stock (บาท)
▸ เส้นกลาง = ค่ากลาง แถบรอบเส้น = ช่วงที่เป็นไปได้ ดาว = จุดที่เราอยู่วันนี้ เพชร = เป้าที่เลือก
▸ ใช้ปุ่มเป้าสำเร็จรูป 3 ปุ่ม หรือเลื่อน slider เพื่อเลือกเป้า

ปุ่ม 1 = ส่งทันเท่าวันนี้ ด้วย stock น้อยสุด ปุ่ม 2 = stock เท่าวันนี้ ส่งทันได้สูงสุด ปุ่ม 3 = เป้าสูงสุดที่ปุ่มเสนอ (ดูตัวเลขบนปุ่ม)
แถบกว้างมากเพราะข้อมูลบอกไม่ได้แน่ชัดว่าบริษัทสั่งเติมเมื่อ stock เหลือกี่เดือน ให้อ่านเป็นทิศทาง ไม่ใช่ตัวเลขแน่นอน
ตอนนี้ PEM101 อยู่ใกล้เส้นที่ดีที่สุดแล้ว ความต่างระหว่างดาวกับปุ่ม 1 เล็กกว่าความคลาดเคลื่อนของ model จึงพูดไม่ได้ว่าลด stock ได้

### ต้นทุนการยกระดับ (PEM101)
▸ ถ้าจะขยับการส่งทัน จากวันนี้ไปถึงเป้า ต้องเพิ่ม stock กี่ %
▸ ตัวอย่าง: ถ้าขึ้น "+20.0% (ช่วง +10.0% ถึง +30.0%)" หมายถึงต้องถือของเพิ่มประมาณ 1 ใน 5 จากที่ถืออยู่ แย่สุด 30%

ตัวเลขนี้แม่นกว่ามูลค่าเป็นบาทในกราฟ เพราะสิ่งที่ข้อมูลบอกไม่ได้ คือบริษัทสั่งเติมเมื่อของเหลือกี่เดือน หักล้างกันเองเมื่อคิดเป็น % ใช้ตัวนี้เวลาคุยเรื่องงบ
กราฟนี้ calibrate จากชุดสินค้าก่อนแบ่งประเภทใหม่ ต่างจากชุดปัจจุบันเล็กน้อย ดูป้ายบนกราฟ
ถ้าเลือกเป้าต่ำกว่าวันนี้ จะเห็นเป็น "ลด stock ได้ …%" แทน

### ตัวควบคุม Tier A (ทุกฝ่าย) — เครื่องมือ "ถ้าเป็นแบบนี้ล่ะ"
ส่วนนี้ใช้สมมติฐานที่ยังไม่ได้ calibrate กับข้อมูลจริง

| ตัวควบคุม | คืออะไร | ค่าเริ่มต้น |
|---|---|---|
| Procurement lead time | สั่งวัตถุดิบถึงได้ของกี่วัน | {ctl_lead_time} |
| Assembly time | ประกอบกี่วัน ไม่มีข้อมูลจริง เป็นค่าเดา | {ctl_assembly} |
| Review interval | ทบทวน stock ทุกกี่วัน | {ctl_review} |
| Cycle service level | อยากให้แต่ละรอบเติมไม่ขาดของกี่ % | {ctl_service_level} |
| Holding cost rate | ต้นทุนถือของต่อปี % ของมูลค่า | {ctl_holding_cost} |
| เลือกคลัง | คลังไหนนับเป็นของขายได้ | ตาม config |
| เกณฑ์ Excess stock (stock เกินจำนวนเดือนที่ตั้ง) | stock พอขายเกินกี่เดือนถือว่าเกิน | ตาม config |

### นโยบายการผลิต (MTS / MTO)
▸ สินค้าแต่ละตัวถูกจัดเป็น เก็บ stock / ผลิตตามสั่ง / ยังไม่ชัด — เฉพาะ "เก็บ stock" ที่มี Min/Max
▸ ผลิตตามสั่งกับยังไม่ชัด อยู่ตารางแยกด้านล่าง

ตัดสินจากป้ายใน DB (cube_Sale_APD) (MTS / MTO / ETO) คู่กับพฤติกรรมจริง {signal_count} อย่าง มีของในคลังตอนนี้ / ส่วนใหญ่ผลิตเป็น batch ไว้ก่อนลูกค้าสั่ง / ส่งได้ภายใน {notice_days} วันหลังรับ PO
- เก็บ stock = ป้าย MTS และพฤติกรรมตรงอย่างน้อย {min_signals} ใน {signal_count}
- ผลิตตามสั่ง = ป้าย MTO หรือ ETO และพฤติกรรมตรงน้อยกว่า {min_signals} อย่าง
- ยังไม่ชัด = ป้ายกับพฤติกรรมขัดกัน หรือป้ายไม่ชัด ให้ฝ่ายยืนยันก่อนตั้ง Min/Max

เกณฑ์ {notice_days} วันและสัดส่วนต่างๆ เป็นสมมติฐาน

### เลือกคลัง
▸ ติ๊กเอาคลังเข้าหรือออกจากการนับเป็นของขายได้ stock ที่มี เดือนที่พอขาย Excess Min value และธง Excess stock จะเปลี่ยน
▸ Min/Max ไม่เปลี่ยน เพราะคำนวณจากยอดขาย ไม่ได้ใช้ stock ปัจจุบัน

### เกณฑ์ Excess stock
▸ สินค้าที่ stock พอขายเกินจำนวนเดือนที่ตั้ง จะขึ้นธง Excess stock
▸ สินค้าที่มีของแต่ไม่มี Forecast เลย แยกเป็นรายการ "สินค้าที่มีของแต่ไม่มี Forecast"

กล่องสรุป — Value of Min level (มูลค่าตาม Min จำลอง = Min × ต้นทุนต่อชิ้น) / ต้นทุนถือของต่อปี / จำนวนสินค้าที่มี Min-Max

### กราฟ Stock value vs Cycle Service Level
▸ ยิ่งอยากไม่ขาดของ ต้องถือของเพิ่มแค่ไหน
▸ แกน X = cycle service level ({csl_min}-{csl_max}) · แกน Y = มูลค่า stock (บาท)
▸ เส้นชันขึ้นช่วงท้าย = ช่วงที่เพิ่ม service อีกนิดต้องจ่ายแพงมาก

### กราฟ Min เทียบกับค่าปัจจุบัน
▸ Min ที่จำลองได้ เทียบกับ Min ค่าที่ตั้งใน DB (Cube_Inventory_Exact)
▸ แกน X = รหัสสินค้า · แกน Y = จำนวน (ชิ้น)
▸ ค่าที่ตั้งใน DB (Cube_Inventory_Exact) คือ Min/Max ที่บันทึกไว้ใน DB (Cube_Inventory_Exact) คนสั่งของใช้ดูประกอบการสั่ง แต่ยังไม่ได้ตรวจว่าตั้งไว้เหมาะสมหรือไม่ จึงใช้เป็นตัวเทียบเท่านั้น
▸ Max ที่แสดงว่า "ไม่ได้กรอก" คือรายการที่ไม่ได้ใส่ค่า Max ไว้ใน DB (Cube_Inventory_Exact)

ตารางรายสินค้า — Min / Max / Min (ค่าที่ตั้งใน DB (Cube_Inventory_Exact)) / Max (ค่าที่ตั้งใน DB (Cube_Inventory_Exact)) / Months of cover (∞ = ไม่มี Forecast) / Excess Min value (มูลค่า Min ส่วนเกิน) = ถ้า Min ใน DB (Cube_Inventory_Exact) สูงกว่าที่จำลอง ส่วนเกินคิดเป็นเงินเท่าไหร่

### ระวัง
- ตัวเลขบนหน้านี้ต่างเล็กน้อย ดูตัวเลขบนหน้า Min-Max เพราะหน้านี้ประมาณจากข้อมูลรายเดือน
- Placeholder และ Excluded อยู่ตารางแยก ไม่มี Min-Max


### วิธีคำนวณ calibration ใหม่ (PEM101)
▸ calibration คือการปรับ Min/Max ให้ตรงกับการส่งของจริง ไม่มีงานอัตโนมัติรันให้ คนเป็นผู้ตัดสินใจว่าจะรันเมื่อไร (เช่น เมื่อมีข้อมูลส่งของใหม่ที่เปลี่ยนภาพไปมาก)
▸ ขั้นตอน
▸ ขั้นที่ 1: ดึงข้อมูลส่งของจริงของสินค้า {n_calibration_items} รายการ ช่อง Omni Channel จาก DB (Cube_CES) (ผู้ดูแลระบบรันคำสั่งดึงข้อมูลเฉพาะกิจ ไม่มีงานอัตโนมัติ)
▸ ขั้นที่ 2: คำนวณ calibration ด้วยสคริปต์ calibration (ใช้ข้อมูลขั้นที่ 1)
▸ ขั้นที่ 3: สร้างข้อมูลของหน้า Min-Max ด้วยสคริปต์สร้างข้อมูล Min-Max
▸ ขั้นที่ 4: สร้างหน้า Min-Max Production Plan แผนวัตถุดิบ และแท็บสรุปผู้บริหารใหม่ แล้วรันชุดทดสอบก่อนใช้
▸ ทุกครั้งที่รัน Min และ Max ของสินค้า PEM101 ที่เก็บ stock ทั้ง {n_calibration_items} รายการจะเปลี่ยน Production Plan และแผนวัตถุดิบเปลี่ยนตาม ควรแจ้งฝ่ายที่ใช้ตัวเลขก่อนรัน
▸ ข้อมูลที่ใช้ปรับครั้งล่าสุดดูได้จากวันที่ "ปรับให้ตรงกับผลจริงเมื่อ" บนหน้า Min-Max

## แท็บ Trend Price List Omni ปี 67–69

ข้อมูลขายใน DB (cube_Sale_APD) ถึง {trend_data_through} อัปเดตทุกเดือนพร้อมหน้าอื่น ใช้ฐาน {n_codes_trend} รหัส หน้าอื่นใช้ {n_codes_pages} รหัส ถ้าสองเลขนี้ต่างกัน เทียบตัวเลขข้ามหน้าตรงๆ ไม่ได้

ใช้ตอบ — สินค้าแต่ละตัวขายแบบไหน ยอดขึ้นลงยังไง

ตัวกรองด้านบน ฝ่าย / หมวด / ประเภท / รูปแบบการขาย / ค้นหา มีผลกับทุกกราฟและตาราง ยกเว้น เส้นเฉลี่ยมีผลแค่กราฟ ① และกราฟในหน้ารายสินค้า และปุ่มหน่วย บาท-จำนวน มีผลกับกราฟ ① ④ และตัวเลขสรุป

### กราฟ ① Trend รวมรายเดือน
▸ ยอดขายรวมแต่ละเดือนของสินค้าที่เลือก
▸ แกน X = เดือน ({trend_first_month} - {trend_last_month}) · แกน Y = บาท หรือ ชิ้น ตามปุ่มหน่วย
▸ แท่งเข้ม = ส่งแล้ว แท่งอ่อนซ้อนบน = PO ที่รับแล้วยังไม่ส่ง เส้นประ = ค่าเฉลี่ยเคลื่อนที่
▸ แท่งสุดท้ายจางเพราะเดือนยังไม่จบ คลิกแท่งเพื่อดูรายวัน

### กราฟ ② แผนที่รูปแบบการขาย (ADI × CV²)
▸ สินค้าแต่ละตัวขายบ่อยแค่ไหน ขนาดออเดอร์แกว่งแค่ไหน
▸ แกน X = ADI (ขายห่างกันกี่เดือน) · แกน Y = CV² (ออเดอร์แกว่งแค่ไหน)
▸ เส้นแบ่ง 4 ช่อง ซ้ายล่าง Smooth ซ้ายบน Erratic ขวาล่าง Intermittent ขวาบน Lumpy
▸ วงใหญ่ = ยอดขายสูง ขนาดวงคิดจากบาทเสมอ ไม่ตามปุ่มหน่วย ค่าเกินขอบถูกตรึงไว้ที่ขอบ คลิกวงเพื่อดูรายสินค้า

สินค้ามุมขวาบน (Lumpy) Forecast ยากสุด ต้องเผื่อ stock มากสุด

### กราฟ ④ ยอดรวมแยกฝ่าย
▸ ความยาวแท่ง = ยอดรวม (บาทหรือชิ้น) · แต่ละแถว = ฝ่าย
▸ คลิกแท่งเพื่อกรองเฉพาะฝ่ายนั้น คลิกซ้ำเพื่อยกเลิก

### ตาราง ③ รายสินค้า
เรียงได้เฉพาะ 4 คอลัมน์ รหัส / ADI / Qty รวม / ยอดขาย แสดงสูงสุด 400 แถว คลิกแถวเพื่อดูรายสินค้า
คอลัมน์ Remark (Match / Check spec ฯลฯ) ไม่มีบันทึกว่าคำนวณยังไง ใช้อ้างอิงเท่านั้น

## แท็บ สรุปผู้บริหาร

เปิดยังไง — กดแท็บ สรุปผู้บริหาร ที่แถบด้านบนของ Dashboard

ใช้ตอบ — ปีนี้ขายไปแล้วเท่าไหร่ คาดว่าทั้งปีจะเท่าไหร่ และ Forecast แม่นพอจะเชื่อไหม แยกตามฝ่าย

ข้อมูลมาจาก
- ยอดขายจริงมาจาก DB (cube_Sale_APD) นับตามเดือนที่ต้องส่งของ รวม PO ที่รับแล้วแต่ยังไม่ส่ง (MPS) ไม่รวม VAT
- Forecast มาจากรอบพยากรณ์ล่าสุด ดูรายละเอียดในหน้ายอดขาย
- ข้อความใต้ตารางบอกว่ายอดจริงถึงเดือนไหน

ขอบเขต — เฉพาะสินค้าใน Price List ช่อง Omni Channel ฝ่ายที่ไม่ได้ทำ Forecast ขึ้นเป็นแถวพร้อมหมายเหตุ ไม่มีตัวเลข (PEM104 ผลิตตามสั่งทั้งหมด)

อ่านยังไง
- การ์ดด้านบน = ยอดขายสะสมเทียบช่วงเดียวกันปีก่อน · คาดการณ์ทั้งปี · ความแม่นของ Forecast เทียบกับ Naive (ใช้ยอดเดือนล่าสุดเป็น Forecast ทุกเดือน) · เรื่องที่ต้องระวัง
- คาดการณ์ทั้งปี = ยอดจริงถึงเดือนข้อมูลล่าสุด + เดือนที่เหลือใช้ค่าที่มากกว่าระหว่าง Forecast กับออเดอร์ที่รับแล้ว × ราคาขายเฉลี่ยจริง
- Relative MAE = MAE ของเรา ÷ MAE ของ Naive ยิ่งต่ำยิ่งดี ถ้าต่ำกว่าของ Naive แปลว่า Forecast ดีกว่า ผลที่ขึ้นว่าถึงเกณฑ์ยังเป็นเกณฑ์ร่าง ไม่ใช่ข้อสรุป
- เรื่องที่รอผู้บริหารตัดสิน = เกณฑ์ร่างที่ยังไม่มีใครยืนยัน

## Production Plan (แผนผลิต)

เปิดยังไง — กด Production Plan (แผนผลิต) ที่แถบด้านบนของ Dashboard จะเปิดหน้าใหม่

ใช้ตอบ — แต่ละเดือนข้างหน้าต้องผลิตสินค้าอะไรเท่าไหร่ ให้พอขายและเติม stock ถึง Max

ข้อมูลมาจาก
- stock มาจาก DB (Cube_Inventory_Exact) ใช้การดึงรายวันล่าสุดตอนสร้างแผน (หน้านี้สร้างใหม่ทุกเดือน) เวลาที่ดึงอยู่ใต้หัวข้อของหน้า
- ออเดอร์ที่รับแล้วแต่ยังไม่ส่งมาจาก DB (Cube_CES)
- ประวัติการผลิตมาจาก DB (cube_final) ชื่อสินค้ามาจาก DB (Cube_ItemList)
- Forecast มาจากรอบพยากรณ์ที่หน้าบอกไว้ใต้หัวข้อ

ขอบเขต — สินค้าใน Price List ทุกฝ่าย Forecast นับเฉพาะช่อง Omni Channel ข้อยกเว้นมีป้ายกำกับบนหน้า
- รวมทุกช่องทาง = stock และออเดอร์ที่รับแล้วนับทุกช่องทาง เพราะใช้ร่วมกัน
- เฉพาะ Omni (ไม่รวมงานประมูล) = ออเดอร์ของ PEM103 นับเฉพาะช่อง Omni Channel ถ้าการดึงล่าสุดยังไม่มีข้อมูลช่องทาง หน้าจะบอกว่าใช้ข้อมูลที่ดึงไว้ก่อนหน้า

อ่านยังไง
- มีหนึ่งตารางต่อฝ่าย คอลัมน์เดือน = จำนวนที่แผนให้ผลิตในเดือนนั้น สินค้าที่เก็บ stock = ผลิตให้ stock ถึง Max สินค้าที่ไม่เก็บ stock = ผลิตตามความต้องการ
- หมายเหตุใต้ตารางของแต่ละฝ่ายบอกสิ่งที่ไม่ได้อยู่ในแผน เช่น รหัสที่ยังไม่มี Forecast (แผนนับเฉพาะออเดอร์ที่รับแล้วแต่ยังไม่ส่ง) รหัสที่ไม่มีบันทึกผลิตใน DB (cube_final) (แสดงยอดความต้องการ ไม่ใช่ยอดผลิต) และฝ่ายที่ผลิตตามสั่งทั้งหมดซึ่งไม่ได้ทำ Forecast
- Historical peak (ยอดผลิตเสร็จสูงสุดต่อเดือนในอดีต ไม่ใช่กำลังผลิตเต็มที่) ใช้ดูทิศทาง
- รหัสที่ไม่พบใน DB (Cube_ItemList) มีหมายเหตุท้ายหน้า ตัวเลขในแผนไม่เปลี่ยน

## แผนวัตถุดิบ

เปิดยังไง — กด แผนวัตถุดิบ ที่แถบด้านบนของ Dashboard จะเปิดหน้าใหม่

ใช้ตอบ — วัตถุดิบตัวไหนต้องสั่งเมื่อไหร่ ให้ทันแผนการผลิต

สถานะ — แผนนี้เป็นร่าง (Draft) ยังอยู่ระหว่างตรวจสอบ ตัวเลขต้องสั่งยังใช้สั่งซื้อจริงไม่ได้ จนกว่าจะกำหนดเกณฑ์ว่าตรงกับใบสั่งซื้อจริงแค่ไหนถึงใช้ได้ (ดูแท็บสมมติฐานที่ใช้อยู่)

ข้อมูลมาจาก
- ความต้องการวัตถุดิบคิดจากแผนการผลิตรอบเดียวกับหน้า Production Plan
- สูตรวัตถุดิบมาจาก DB (Cube_BOM_Exact) stock วัตถุดิบมาจาก DB (Cube_Inventory_Exact) ของที่สั่งแล้วรอรับมาจาก DB (Cube_tobe_received) ชื่อและประเภทสินค้ามาจาก DB (Cube_ItemList) ข้อมูลหน่วยซื้อมาจาก DB (Cube_PriceList)
- เวลาที่ดึง stock วัตถุดิบอยู่ใต้หัวข้อของหน้า

ขอบเขต — ฝ่ายที่มียอดผลิตในแผน (PEM104 ไม่มียอดผลิตในแผน จึงไม่มีวัตถุดิบ) ป้าย รวมทุกช่องทาง (ยกเว้น PEM103) = ความต้องการมาจากแผนการผลิตที่นับออเดอร์ทุกช่องทาง ยกเว้น PEM103 ที่นับเฉพาะ Omni Channel

อ่านยังไง
- ต้องสั่งภายในช่วงที่หน้ากำหนด = วัตถุดิบที่ต้องสั่งในช่วงนั้น ถึงจะได้ของทันตามแผน
- เลยกำหนดสั่ง (Late to order) = สั่งวันนี้ของมาไม่ทันแผน ให้ตรวจของที่มีอยู่จริง หรือเร่งของที่สั่งไว้แล้ว
- ของที่สั่งแล้วรอรับ นับตามวันที่คาดว่าจะได้
- รายการที่เป็นค่าแรง ค่าจ้าง ค่าบริการ หรือไม่ใช่สินค้า ไม่ต้อง stock จึงไม่นับ รายการที่ขึ้นว่ารอตรวจ ยังนับไว้จนกว่าจะมีคนยืนยัน
- สินค้าในแผนการผลิตที่ไม่ได้คิดวัตถุดิบ มีสรุปเหตุผลใต้หัวข้อของหน้า

## แท็บ S&OP Plan (เดิม)

ทั้งแท็บเป็นตัวอย่างสำหรับนำเสนอ พิมพ์ไว้ครั้งเดียว ไม่อัปเดต ห้ามใช้ตัวเลขในแท็บนี้ตัดสินใจ ยกเว้นแผง stock จริงที่เปิดจากแถว Inventory

- ตัวเลขสรุปด้านบน — ค่าคงที่ ไม่ได้คำนวณจากระบบ
- ส่วนที่ 1 ตารางรายเดือน — สีฟ้า = History สีส้ม = Plan (ตัวอย่าง) คอลัมน์ Odoo Module เป็นข้อเสนอ ยังไม่ได้เชื่อมจริง
- ส่วนที่ 2 กราฟ Actual vs Forecast — แกน X = เดือน ม.ค.-ธ.ค. แกน Y = ยอดขาย (ล้านบาท) เส้นทึบ = ยอดจริง เส้นประ = ตัวอย่างการพยากรณ์ ชี้เมาส์ไม่มีค่าขึ้น
- ส่วนที่ 4 ตารางรายสินค้า — ป้าย "ข้อมูลจริง" / "ตัวอย่าง" บอกแต่ละแถว Min/Max ทุกแถวเป็น "คำนวณตัวอย่าง" ตัวกรองแค่ซ่อนแถว
- ส่วนที่ 5 — ปัจจัยสภาพอากาศและการจัดซื้อการไฟฟ้า ยังไม่ได้นำมาใช้จริง

## ข้อมูลอัปเดตเมื่อไหร่

- แผง stock อัปเดตอัตโนมัติทุกวันทำการ (จันทร์ถึงศุกร์) หน้ายอดขาย หน้า Min-Max และแท็บ Trend Price List Omni ปี 67–69 อัปเดตอัตโนมัติทุกเดือนในวันธรรมดา (จันทร์ถึงศุกร์) วันแรกตั้งแต่วันที่ {run_day_base}
- ข้อมูลเดือนไหนจะนำมาใช้ต้องรอ {guard_days} วันหลังสิ้นเดือน ให้รายการที่คีย์ช้าเข้า DB (cube_Sale_APD) ครบ ข้อมูลล่าสุดของหน้ายอดขายและหน้า Min-Max จึงช้ากว่าปัจจุบันประมาณ {lag_months} เดือน ส่วนแท็บ Trend Price List Omni ปี 67–69 ใช้ข้อมูลจนถึงวันที่ดึงล่าสุด ({trend_data_through})
- แท็บ S&OP Plan (เดิม) ไม่อัปเดต

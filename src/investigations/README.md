# Investigation scripts

This directory holds every **one-time investigation, audit, or analysis** script written
during this project — as opposed to the scripts in `src/` (one level up), which are the
**pipeline components** `src/run_pipeline.py` actually runs, in order, on every reproduction
of this project's current results (see that script's own docstring for the run order, and
`STATUS.md`'s "Phase B closeout" log entry for the closing task that built it).

**Nothing here has been deleted.** Every script below already ran to completion at least
once; its findings are recorded in `STATUS.md` (cited per script below) and its raw output
lives in `output/summary/` and `output/data/` (not committed — CONVENTIONS.md: never commit
generated output, it can always be regenerated by re-running the script). Moving a script
here does not retract its findings — it marks that the QUESTION it was written to answer has
been answered and folded into `STATUS.md`, not that the script stopped mattering.

**Why these scripts moved and the pipeline components did not**: `src/run_pipeline.py`
reproduces this project's CURRENT adopted method end to end from a fresh database pull. A
script belongs there only if reproducing the pipeline requires running it every time. Every
script in this folder instead answered a specific, one-time question (a data-quality check,
a hypothesis test, a comparison between candidate methods) whose answer is now a fixed fact
recorded in `STATUS.md` — re-running it would recompute a settled question, not reproduce the
adopted forecast.

**These scripts still run** if invoked directly (`python src/investigations/<script>.py` from
the project root) — moving them required updating each script's `PROJECT_ROOT` (now three
directory levels up, not two) and its `sys.path.insert(...)` (now pointing at `src/`, so
`from db import run_query`, `from models import ...` etc. still resolve to the pipeline
components that stayed in `src/`). This was verified by running a sample script from its new
location after the move, not assumed.

## How to read the table

**STATUS.md entry supported** cites the section heading or dated log entry in `STATUS.md`
whose findings this script produced — search `STATUS.md` for that exact text to find the full
write-up, confidence level, and evidence. Several scripts feed the same STATUS.md entry
(a phase's findings are often built from more than one script); several STATUS.md entries are
themselves supported by more than one script working together (data pull, then analysis, then
report) — both are noted where relevant.
